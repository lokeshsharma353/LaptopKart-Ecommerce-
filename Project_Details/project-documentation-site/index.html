LaptopKart — everything about this project, in one place

A Salesforce Experience Cloud (LWR) e-commerce storefront: guest-user checkout, a custom login system, a Razorpay payment-gateway integration, and a full Lead→Order→Payment automation chain built on standard and custom objects. LWC Component Architecture

Eight top-level page components, each composed from smaller child components. The full per-component breakdown (including every service-module dependency) is in the LWC & Service Reference table below.

Two catalogs exist. The real, Apex-backed catalog flows ProductCatalogController.getProducts() → productDataService.js. A separate mockProductData.js module (12 hardcoded non-laptop products) is a legacy/demo artifact not wired into any page read in this audit.

Diagram 5 of 7

Admin & Backend Flow

Guest Users can't own records long-term, so every record created during checkout is reassigned to a real admin user at the end of the pipeline (Step 10). This is what the admin actually sees and can act on afterward.

Diagram 6 of 7

Razorpay Payment Gateway

A full-page redirect flow, not an embedded widget — this org's Lightning Web Security blocks the dynamic <script> injection Razorpay's Checkout.js needs, so the gateway's own JS never loads inside the Salesforce page at all.

Two Authentication Systems

A common point of confusion in this codebase: two completely independent login systems coexist, and a shopper can have an account in one without ever touching the other.
